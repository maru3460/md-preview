# プレビューにコメント → Claude Code へ貼り付け（設計）

## 目的

difit の「差分の行にその場でコメント → 全部コピーして AI に渡す」体験を、Markdown
プレビューに移植する。レンダリング済みの本文を読みながら気軽にコメントを付け、まとめて
コピーして Claude Code へ貼れるようにする。既存の右クリック／IPC 基盤とクリップボード
処理の上に載せる。

コメントの真実の持ち主は JS 配列。各コメントは `{ file, startLine, endLine, quote, body }`
を持ち、「全部コピー」で 1 枚のテキストへ畳んでクリップボードに入れる。貼り先の
Claude Code がファイルを開き・grep で位置を当てやすい形にするのが要件。

## 決定事項

### 操作モデル: コメントモードのトグル

ツールバーのボタン（または `c` キー）で「コメントモード」に入る。モード中は本文の各
ユニットにホバーで左に `+` ハンドルが出て、クリックでそのユニットを対象にコメント入力
ポップオーバーが開く。`Esc` でポップオーバー → モードの順に閉じる。

### コメントの粒度: 行／要素単位（ブロックではない）

- リストは**項目（`li`）ごと**、表は**行（`tr`）ごと**、コードブロックは**1 行ごと**に
  コメントできる。見出し・単独の段落はそれ自体が 1 ユニット。
- **mermaid / drawio 図はブロック単位**でコメントする（行分割しない）。
- **複数行はドラッグ選択**でまとめて 1 コメントにできる（レンジ）。

段落の割り切り: Markdown の段落は複数のソース行を 1 つの段落として書くことが多く、
レンダリング後は 1 つの `<p>` に溶ける。したがって**段落は 1 ユニット**（開始行〜終了行の
レンジ）として扱い、文（センテンス）単位には割らない。リスト項目・表の行・コード行は
1 行ずつ割れるので、行コメントの粒度はそこで担保する。

### 出力形式（「全部コピー」でクリップボードに入る内容）

- ファイル行は `- ` 始まり。単一行は `:line`、レンジは `:start-end`。
- 引用は `>` ブロック。**引用の直後に空行を 1 行**入れる。これを入れないと、続く
  ユーザーコメントの行まで Markdown の blockquote に飲まれてしまうため。
- ユーザーのコメントは引用の外（素のテキスト）。
- 行番号が解決できないユニットは `:line` を省いて `- docs/plan.md` とする。

```text
- docs/plan.md:15
> 認証は JWT を使う。アクセストークンは短命にして…

リフレッシュトークンの扱いは？

- docs/plan.md:18-20
> POST /auth/token
> { "grant_type": "password", ... }
> → { "access_token": "...", "expires_in": 900 }

このリクエスト、レート制限は？
```

複数ファイルにまたがっても各エントリが自前のパスを持つのでそのまま並べる。引用テキストは
散文なら空白畳み、コード行はそのまま。エントリ間は空行で区切る。

## 体験フロー

1. ツールバーの吹き出しボタン、または `c` でコメントモードに入る（カーソルとホバー表示で
   モード中だと分かる）。
2. 気になったユニットをクリック。複数行はドラッグで選択。近くにポップオーバー（textarea
   ＋保存／取消）が開く（`⌘+Enter` で保存、`Esc` で取消）。
3. 保存すると対象ユニットの左に色帯＋💬バッジが付き、右下のパネルに 1 件追加される。
4. コメント済みユニットにホバーすると、その行の近くに内容がプレビュー表示される
   （モード外でも確認できる）。💬バッジのクリックで編集。
5. 別ユニット・別ファイル（folder モード）へ移ってもパネルにたまり続ける。編集・削除も可能。
6. パネルの「全部コピー」で上記フォーマットが一括でクリップボードへ。Claude Code に貼るだけ。

## 技術設計

### ① 行番号の解決（`file:line` の肝）

全モードの本文生成は `src/html.rs` の `render_body()` 一本に集約されている（single /
stdin と folder モードの `?body=` 経路がここを通る）。ここを
`Parser::new_ext(..).into_offset_iter()` に切り替えると、各イベントにソースのバイト範囲が
付く。元 Markdown の改行位置を先にインデックス化しておき、対象ユニットの開始／終了行を
算出して、開きタグを `data-src-line`（必要なら `data-src-end-line`）付きで自前生成する
（`Event::Html` で置換）。pulldown-cmark 0.13 で `into_offset_iter` が使えることは確認済み。

コメント時は JS が `e.target.closest('[data-src-line]')` で最寄りの行番号を即座に読む。
正確で速い。

対象ユニットの開きタグを肩代わりする必要がある要素:

- 見出し `h1`–`h6`、単独段落 `p`、リスト項目 `li`、表の行 `tr`、コードブロック内の各行、
  blockquote（アラート）。
- コードブロックは 1 行ずつコメントできるよう、各行に `data-src-line` を振る（行の開始
  オフセットから算出）。
- mermaid / drawio は既存の特殊処理（`Event::Html` 置換）のまま、図の外枠に `data-src-line`
  を 1 つ付けてブロック単位で扱う。

既存の特殊処理（アラート引用の見出し注入・ファイル名付きコードブロック・表のスクロール
ラッパ・mermaid / drawio）と共存させる。**この行番号注入が実装の最大の作業**。

**却下した代替案**: 各ブロックを `<div>` で包んで `data-src-line` を持たせる方式。実装は
軽いが `base.css` の子セレクタ（`.markdown-body > h1` 等）や余白（margin collapse）に影響が
出るため採らない。

**フォールバック**: 行番号が取れないユニットは `:line` を省いてファイル名だけで出す。

### ② コンポーネント（新規 `src/comment.js`）

- **トグル＋選択**: モード中だけ本文の `mousedown` / `mouseenter` / `mouseup` を捕捉し、
  単一クリック＝1 ユニット、ドラッグ＝レンジ選択。モード中は `user-select: none` で
  ドラッグがテキスト選択にならないようにする。
- **ポップオーバー**: 対象ユニット近傍に textarea。保存で配列へ push＋マーカー描画。
  画面端ではフリップして収める。
- **ホバー・プレビュー**: コメント済みユニットのホバーで、その行の近くに内容を表示する
  小さな浮遊パネル（複数コメントがあれば並べる）。モード外でも確認できる。
- **パネル**: 右下フロート。件数バッジ・各コメントの編集／削除・「全部コピー」・「全消去」。
  パネルのコメントにホバーすると本文の該当ユニットをハイライトする。
- **コピー**: `navigator.clipboard.writeText` で JS 完結（既存の選択コピーと同じ経路、
  IPC 不要）。失敗時は `textarea`＋`execCommand('copy')` にフォールバック。

### ③ ホットリロード時の再アンカー

ファイルを編集すると `loadNormalBody()` が本文 `innerHTML` を差し替え、インラインの
マーカーは消える。配列は生き残るので、リロード後に `file` が現在ファイルと一致する
コメントを `data-src-line`＋引用テキスト照合で貼り直す（best-effort。取れなければパネルには
残す）。

### ④ ファイルパスの解決

- folder モードは `MdMenu.setCurrentFile` 経由で現在ファイルの相対パス（`currentRel`）を
  既に持っている。
- single モードは JS が basename しか知らないので、`src/main.rs` の init_script で
  `window.MD_FILE_REL`（cwd 配下なら cwd 相対、外なら basename）を注入して出力に使う。

### ⑤ セキュリティ

既存 CSP で本文（untrusted な Markdown）の `<script>` は無効。コメント機能は nonce 付きの
自前 JS で、クリップボード書き込みも JS 完結・IPC を介さないため新たな攻撃面は増えない。
`data-src-line` は数値のみで XSS の余地なし。詳細は [security-model.md](security-model.md) を参照。

## スコープ

### MVP（まず出す範囲）

single ＋ folder モード／行・要素単位のクリックコメント／ドラッグでの複数行レンジ／
`data-src-line` による行番号／コメント済みのホバープレビュー／右下パネル／全部コピー。
ホットリロード再アンカーは best-effort。対象は **Markdown 本文のみ**。

### 後回し（今回はやらない）

- 非 md のソース表示（source-page）・html iframe 内へのコメント
- 段落を文（センテンス）単位に割る細かい粒度
- **コードブロックの 1 行単位コメント**（初回実装ではブロック全体を 1 ユニット扱い＝
  `:start-end` の行レンジで付ける。1 行ごとの `data-src-line` は hljs ハイライトと
  衝突するため、ハイライト後もマーカーを保つ追加実装が要る。当面はブロック単位）
- **表の 1 行単位コメント**（`tr` の開きタグを置換すると pulldown-cmark の push_html が
  持つテーブル状態機械（`table_state`/`table_cell_index`）が更新されず、本文セルの
  アライメント消失・2 つ目以降のテーブルでヘッダが `<td>` 化する回帰が出る。そのため
  当面は**表全体を 1 ユニット**（`.table-wrap` に `data-src-line`）として扱う。行単位に
  するには、行/セルの `Start` を潰さずに行番号を載せる方式（セル側 or 生成後の後処理注入）が要る）
- コメントのファイル保存・永続化（セッション内メモリのみ）

## 検討メモ（決着済み）

- 行番号は「開きタグ肩代わり」方式を採用（DOM がきれい）。ラッパ div 方式は CSS 影響で不採用。
- 粒度はブロック単位ではなく行・要素単位。段落だけは 1 ユニット（レンジ）で割り切る。
- 引用（`>`）の直後には必ず空行を入れる（コメントが blockquote に飲まれるのを防ぐ）。
- コピー冒頭に見出し行は付けず、エントリだけを並べる。
- トグルキーは `c`（既存の `j`/`k`/`d`/`u`/space/`g`/`G`/`/` と非衝突）。
- **マウス無し操作**: モード中はユニット・カーソルを `j`/`k`（`↑`/`↓`）で移動、`Shift+j`/`Shift+k` で
  レンジ伸縮、`Enter` で付与。モード中の `j`/`k` は keyscroll から譲ってもらい（`MdComment.isMode`）、
  `d`/`u`/`Space`/`g`/`G` のページ送りはモード中もそのまま効かせる。
- パネルは右下フロート。diff/raw トグル（右下 bottom 16/56px）と重ならないよう bottom 96px に積む。
- **パネルの表示＝コメントモードの ON/OFF**。モードを抜けたらパネルは畳む（コメント配列は
  保持し、本文のマーカー／ホバープレビューは残る）。パネルが出ていればモード中、という一目瞭然。
- 全消去は 2 クリック確認（wry の WKWebView は `window.confirm` を出せないため、ダイアログに頼らない）。
- 引用テキストからは 💬 バッジ・Copy ボタン等の UI チップを除外する（clone して取り除いてから抽出）。
- `<details>` / `<summary>` は生 HTML ブロックなので、開きタグに `data-src-line` を注入して
  アコーディオンのトグル自体をコメント対象にする。
