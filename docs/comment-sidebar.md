# コメント一覧のサイドバー統合（設計記録）

コメント一覧パネル（右下フロート）が本文に被って邪魔、という問題への対応の記録。
今回実装した「タブ化」と、次回に持ち越した「インライン埋め込み」の両方をここに残す。

## 問題

- コメント一覧（`.md-cmt-panel`、右下 320px・max-height 60vh）はモード中ずっと本文に
  被さる。TOC は `body.md-toc-open` の右ガターで「本文が避ける」構造を持っているのに、
  コメント一覧はそれを使っていなかった。
- 入力ポップオーバー（300px）が狭く、長いコメントが書きづらい。

## 決定事項（今回実装）

### 右サイドバーのタブ化（塗り替えモデル）

TOC サイドバー（`.md-toc-panel`）にコメント一覧を Comment タブとして載せる。ガター
（本文が左へ避ける仕組み）は既存の `md-toc-open` をそのまま共有する。folder モードの
ガターが `#preview-pane` 側に付く特殊扱いも既存 CSS がそのまま効く。

タブの並列は見せず**まるごと置き換え式**: 普段は Outline だけで、モード中はヘッダの
タイトルごと Comment に置き換わる（Outline はモード中は見えない）。Outline=ただの表示、
Comment=モード、という非対称なものをタブで対等に見せない（違和感の元）ため。また
「Outline タブのクリックが実はモード終了」という副作用付きタブも作らない。
モードの入口はピル / `c` / バッジ / 右クリックメニュー、出口は × / Esc / `c` / ⌘T。

### モードとタブの対応

- **コメントタブ表示中 ＝ コメントモード**。閲覧専用状態は作らない
  （モードがコメント閲覧を兼ねる。キーボード導線 n/p/e/x を二重に定義しないため）。
- モードに入る経路（💬 ピル・バッジクリック・`c`・右クリックメニュー）すべてで
  サイドバーが Comment タブで開く（0 件でも空一覧で開く）。
- モードを抜けたら**入る前のサイドバー状態に復元**する（Outline を開いていた人は
  Outline へ、閉じていた人は閉じる）。ただしユーザーの明示操作は復元より優先:
  - サイドバーの × で抜けた → サイドバーごと閉じる（userClosed 扱い）
  - ⌘T は Comment 表示中なら「Outline へ切替（＝モード終了）」
- **コメントタブに幅による自動退避は適用しない**（手動で出したものは出しっぱなし）。
  TOC の自動退避（`MIN_WIDTH`）は Outline 表示時のみ評価する。

### 一覧のハイライト（2 段階）

- **in-view（薄）**: アンカーが画面内にあるコメント。複数同時にあり得る。
  スクロールで受動的に変わる。
- **review（強）**: n/p の巡回対象（`reviewId`）。常に 1 件。n/p か一覧クリックでだけ
  動く。巡回時は一覧側も `scrollIntoView({block:'nearest'})` で追従する。
- 「再生中の曲」と「見えてる曲」の関係。役割を完全に分けることでマウス/キーボードの
  噛み合い問題を回避する。
- 一覧の並び順は挿入順から **file→行順（`sortedComments`）** に変更。n/p の巡回順・
  全部コピーの出力順と一致させ、巡回が一覧を上から下へ歩くようにする。

### フォームの改善

- ポップオーバー幅 300px → 380px。
- textarea は入力に合わせて自動で縦に伸びる（上限 40vh、超えたらスクロール）。
  手動リサイズは廃止（自動グローと競合するため）。伸びたら再配置して画面内に収める。
- サイドバー共通幅 `--md-toc-w` を 260px → 300px に拡大。

## 却下した案

- **線で繋ぐ案**（サイドバー項目と本文アンカーを SVG で結ぶ）: スクロール・リサイズ・
  ホットリロードのたびに再計算が必要で、片方が画面外のときの見せ方が本質的に決まらない。
  実装・保守が重いわりに、解決するのは「対応関係の表示」だけでハイライトで足りる。

## 次回: インライン埋め込み（GitHub 風）

**モード中限定**で、コメントをアンカーユニットの直下に埋め込み表示する案。未実装。

### なぜやりたいか

- コメントがアンカー直下に出れば「対応関係の表示」という問題自体が消滅する。
  マウス/キーボードの噛み合いも悩む余地がなくなる（n/p はただ次の埋め込みへ
  スクロールするだけ）。
- ホバープレビュー（`.md-cmt-preview`）の上位互換になる。
- 今回のサイドバーは無駄にならない: 埋め込みが「読む」を担い、サイドバーは
  「一覧・ジャンプ・件数把握（特に folder モードの別ファイル分）」に役割が寄る。
  ハイライトの重要度が自然に下がるだけ。

### 実装時の論点（今回の調査で分かっていること）

- 本文 DOM にブロックを差し込むので、以下と干渉する:
  - **レイアウトシフト**: モード出入りで本文の高さが変わる。スクロール位置の補正が要る。
  - **ホットリロード**: `redraw()` が markers を貼り直す構造（`comment.js` の
    `invalidateKbUnits` / `reanchor`）に埋め込みの貼り直しも乗せる必要がある。
  - **ユニット選択**: ドラッグのレンジ判定は `allUnits(host)`（`[data-src-line]` の
    スナップショット）で行っている。埋め込み要素は `data-src-line` を持たせない・
    `contenteditable=false`（バッジと同じ扱い）にして選択対象から外す。
  - **レンジコメント**は範囲の**最後のユニットの直後**に差し込む。
- バッジ（`.md-cmt-badge`）はユニット内に append する前例。埋め込みはユニットの
  **兄弟**として after に置く方が、ユニット自身のレイアウトを壊さない。
- 編集/削除の UI を埋め込み側にも持たせるか（GitHub は持つ）はそのとき決める。
- タブ化（サイドバーの所有権リファクタ）と同時にやらず、別コミットで切り分ける
  ——壊れたときの原因切り分けのため。今回はタブ化まで。
