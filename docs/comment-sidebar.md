# コメント一覧のサイドバー統合（設計記録）

コメント一覧パネル（右下フロート）が本文に被って邪魔、という問題への対応の記録。
今回実装した「タブ化」と、次回に持ち越した「インライン埋め込み」の両方をここに残す。

## 問題

- コメント一覧（`.md-cmt-panel`、右下 320px・max-height 60vh）はモード中ずっと本文に
  被さる。TOC は `body.md-toc-open` の右ガターで「本文が避ける」構造を持っているのに、
  コメント一覧はそれを使っていなかった。
- 入力ポップオーバー（300px）が狭く、長いコメントが書きづらい。

## 決定事項（今回実装）

### 右サイドバーのタブ化（塗り替えモデル）

TOC サイドバー（`.md-toc-panel`）にコメント一覧を Comment タブとして載せる。ガター
（本文が左へ避ける仕組み）は既存の `md-toc-open` をそのまま共有する。folder モードの
ガターが `#preview-pane` 側に付く特殊扱いも既存 CSS がそのまま効く。

タブの並列は見せず**まるごと置き換え式**: 普段は Outline だけで、モード中はヘッダの
タイトルごと Comment に置き換わる（Outline はモード中は見えない）。Outline=ただの表示、
Comment=モード、という非対称なものをタブで対等に見せない（違和感の元）ため。また
「Outline タブのクリックが実はモード終了」という副作用付きタブも作らない。
モードの入口はピル / `c` / バッジ / 右クリックメニュー、出口は × / Esc / `c` / ⌘T。

### モードとタブの対応

- **コメントタブ表示中 ＝ コメントモード**。閲覧専用状態は作らない
  （モードがコメント閲覧を兼ねる。キーボード導線 n/p/e/x を二重に定義しないため）。
- モードに入る経路（💬 ピル・バッジクリック・`c`・右クリックメニュー）すべてで
  サイドバーが Comment タブで開く（0 件でも空一覧で開く）。
- モードを抜けたら**入る前のサイドバー状態に復元**する（Outline を開いていた人は
  Outline へ、閉じていた人は閉じる）。ただしユーザーの明示操作は復元より優先:
  - サイドバーの × で抜けた → サイドバーごと閉じる（userClosed 扱い）
  - ⌘T は Comment 表示中なら「Outline へ切替（＝モード終了）」
- **コメントタブに幅による自動退避は適用しない**（手動で出したものは出しっぱなし）。
  TOC の自動退避（`MIN_WIDTH`）は Outline 表示時のみ評価する。

### 一覧のハイライト（2 段階）

- **in-view（薄）**: アンカーが画面内にあるコメント。複数同時にあり得る。
  スクロールで受動的に変わる。
- **review（強）**: n/p の巡回対象（`reviewId`）。常に 1 件。n/p か一覧クリックでだけ
  動く。巡回時は一覧側も `scrollIntoView({block:'nearest'})` で追従する。
- 「再生中の曲」と「見えてる曲」の関係。役割を完全に分けることでマウス/キーボードの
  噛み合い問題を回避する。
- 一覧の並び順は挿入順から **file→行順（`sortedComments`）** に変更。n/p の巡回順・
  全部コピーの出力順と一致させ、巡回が一覧を上から下へ歩くようにする。

### フォームの改善

- ポップオーバー幅 300px → 380px。
- textarea は入力に合わせて自動で縦に伸びる（上限 40vh、超えたらスクロール）。
  手動リサイズは廃止（自動グローと競合するため）。伸びたら再配置して画面内に収める。
- サイドバー共通幅 `--md-toc-w` を 260px → 300px に拡大。

## 追記: raw / プレビューの表示分離 ＋ mermaid バッジ修正

埋め込み実装後に見つかった問題への対応。

- **mermaid の構文エラー**: 💬 バッジはユニット内に append するが、mermaid は
  ユニット（`pre.mermaid`）の textContent がそのまま図のソースで、ホットリロード時は
  hydrate が reanchor（同期・バッジ貼り）→ mermaid.run（非同期・パース）の順に走る。
  「💬」が混ざってパースされ syntax error になっていた。→ mermaid だけ 0 高さの
  `.md-cmt-badge-holder` をユニット直前に挟んでバッジを載せる（見た目は他と同じ
  ブロック右上）。drawio は XML が data 属性なので影響なし。
- **表示の分離**: raw の行コメントがプレビューではブロック全体（段落・コード・
  mermaid）に落ちて錨として粗く、見た目も悪い。→ 本文への描画（マーカー・バッジ・
  埋め込み・ホバー・e/x の対象解決）を「付けた表示と現在の表示が一致するコメント」
  （`inCurrentView`）に限定した。サイドバー一覧は従来どおり全件（横断インデックス、
  raw タグ付き）で、n/p・一覧クリック・e が表示ごと切り替えて着地する既存導線は
  そのまま。folder モードの「別ファイルは一覧にだけ出る」と同じ役割分担。

## 却下した案

- **線で繋ぐ案**（サイドバー項目と本文アンカーを SVG で結ぶ）: スクロール・リサイズ・
  ホットリロードのたびに再計算が必要で、片方が画面外のときの見せ方が本質的に決まらない。
  実装・保守が重いわりに、解決するのは「対応関係の表示」だけでハイライトで足りる。

## インライン埋め込み（GitHub 風）— 実装済み

**モード中限定**で、コメントをアンカーユニットの直下に埋め込み表示する。
タブ化の次のコミットとして実装した。

### なぜやったか

- コメントがアンカー直下に出れば「対応関係の表示」という問題自体が消滅する。
  マウス/キーボードの噛み合いも悩む余地がなくなる（n/p はただ次の埋め込みへ
  スクロールするだけ）。
- ホバープレビュー（`.md-cmt-preview`）の上位互換になる。
- 今回のサイドバーは無駄にならない: 埋め込みが「読む」を担い、サイドバーは
  「一覧・ジャンプ・件数把握（特に folder モードの別ファイル分）」に役割が寄る。
  ハイライトの重要度が自然に下がるだけ。

### 実装の要点（決定事項）

- **描画は redraw() の派生物**: 真実は `comments[]` のまま。埋め込み（`.md-cmt-embed`）は
  redraw が毎回貼り直す（`clearMarkers` が剥がす）ので、ホットリロード・ファイル切替・
  raw 切替にそのまま乗る。モード切替時は `setMode` が redraw を呼んで出し入れする。
- **位置**: ユニットの**兄弟**として直後に `insertBefore(embed, tail.nextSibling)`。
  レンジコメントは `unitsInRange` のトップレベル**最後のユニットの直後**。同じ錨に
  複数コメントが付いたら 1 つの枠に行順でまとめる。
- **選択対象から除外**: `data-src-line` を持たせず `contenteditable=false`（バッジと
  同じ扱い）。mousedown / click(capture) / mousemove の各ハンドラでも
  `.md-cmt-embed` を明示除外——埋め込みが入れ子ユニット（外側 li 等）の中に入る
  ケースで、`closest('[data-src-line]')` が祖先を拾って誤動作するのを防ぐ。
  `unitQuote` のクローン除去にも `.md-cmt-embed` を足した（外側ユニットの引用に
  コメント本文が混入しない）。
- **レイアウトシフト補正**: `anchorScroll(fn)` を新設。基準ユニット（キーボード・
  カーソル、無ければ画面内の最初のユニット）の `rect.top` を DOM 変更の前後で
  合わせ、差分だけ scroller（単一=window / folder=#preview-pane を祖先探索で解決）を
  scrollBy する。モード出入りと CRUD（追加/編集/削除/全消去）の redraw に適用。
- **raw / ソース表示には出さない**: 行レイヤ（`.md-src-row`）は行ボックスの積み上げで
  コードと位置を合わせているので、間にブロックを挟めない。raw のコメントは
  サイドバー一覧で読む。
- **編集/削除 UI は埋め込み側にも持つ**（GitHub と同じ）。編集のポップオーバーは
  埋め込み項目の位置に出す。埋め込み本文はテキスト選択可（モード中の本文は
  user-select:none だが埋め込みだけ text に戻す）。
- 役割分担は狙いどおり: 埋め込みが「読む」、サイドバーが「一覧・ジャンプ・件数把握」、
  ホバープレビューは「モード外の確認」。
